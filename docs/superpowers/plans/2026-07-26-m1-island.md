# Pet Island M1 — The Island Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A playable 3D island: read a word → an egg hatches into a cube pet that lives there; solve a sum → earn a hex tile and place it yourself. Fred greets you and the opening plays.

**Architecture:** Three.js scene over a DOM overlay. The world raises intents; `flow.ts` mediates; the overlay mounts the *already-extracted, already-tested* `challenges/` modules. Nothing crossing that boundary knows about the other side.

**Tech Stack:** Three.js 0.185, the M0 `core/`/`platform/`/`challenges/` packages, Vite PWA, Vitest.

## Global Constraints

- **Reuse M0. Do not re-derive.** Word/sum generation, segmentation, decks, names, speech, audio and all three challenge renderers already exist, are tested, and are proven identical to the frozen original. The island *consumes* them.
- **`v0/junos-words.html` stays frozen.** Untouched, forever.
- **The finger is the player.** No avatar, no character controller (brief §2).
- **Nothing can be lost.** No timers on eggs, tiles or quests; no decay; no failure states (brief §18).
- **Bright, never scary** (brief §1.2). No darkness-as-threat.
- **UK English**, reading-age appropriate.
- **Every unit that can be pure, is.** Hex maths and island state are pure functions over plain data, unit-tested without a GPU.
- Node 20+, npm. Commit after every task.

## Deliberate scope calls

- **M1 ships dressed, not grey-boxed** (spec §7). Real KayKit hex tiles, a real Kenney cube pet, code-built Fred, juice on from Phase 4. Judging "does it feel right" through untextured boxes risks a false negative from the only reviewer who matters.
- **`isActive` and `holds` come from the island's own flow**, not the 2D shell's.
- **No album, variants, habitat coupling, nursery, quests, bands, scheduler, Owl's Book, dashboard, profiles or seasons.** All M2/M3.

## Phase 4 — Island skeleton

### Task 1: Hex coordinate maths (pure)

**Files:** Create `src/island/world/hex.ts`, `tests/island/hex.test.ts`

**Produces:** `Axial {q, r}`, `key(a)`, `parse(k)`, `neighbours(a)`, `toWorld(a, size)`, `distance(a, b)`, `DIRECTIONS`

Flat-top axial coordinates (Red Blob Games convention). `toWorld` maps to x/z with y=0.

- [ ] **Step 1: Write the failing test**

```ts
import { describe, it, expect } from 'vitest'
import { key, parse, neighbours, toWorld, distance } from '../../src/island/world/hex'

describe('hex', () => {
  it('round-trips a coordinate through its key', () => {
    expect(parse(key({ q: 2, r: -3 }))).toEqual({ q: 2, r: -3 })
  })

  it('has exactly six neighbours, all distance 1', () => {
    const n = neighbours({ q: 0, r: 0 })
    expect(n).toHaveLength(6)
    expect(new Set(n.map(key)).size).toBe(6)
    for (const a of n) expect(distance({ q: 0, r: 0 }, a)).toBe(1)
  })

  it('neighbour relation is symmetric', () => {
    const a = { q: 1, r: 2 }
    for (const b of neighbours(a)) {
      expect(neighbours(b).map(key)).toContain(key(a))
    }
  })

  it('places the origin at the world origin', () => {
    expect(toWorld({ q: 0, r: 0 }, 1)).toEqual({ x: 0, z: 0 })
  })

  it('spaces adjacent tiles by exactly one tile width', () => {
    const size = 1
    const a = toWorld({ q: 0, r: 0 }, size)
    for (const n of neighbours({ q: 0, r: 0 })) {
      const w = toWorld(n, size)
      const d = Math.hypot(w.x - a.x, w.z - a.z)
      expect(d).toBeCloseTo(Math.sqrt(3) * size, 5)
    }
  })

  it('distance is symmetric and zero to itself', () => {
    expect(distance({ q: 0, r: 0 }, { q: 0, r: 0 })).toBe(0)
    expect(distance({ q: 3, r: -1 }, { q: 0, r: 2 }))
      .toBe(distance({ q: 0, r: 2 }, { q: 3, r: -1 }))
  })
})
```

### Task 2: Island state (pure)

**Files:** Create `src/island/world/grid.ts`, `tests/island/grid.test.ts`

**Produces:** `TileType = 'grass' | 'water'`, `Island {tiles: Map<string, TileType>}`, `createIsland()`, `place(island, a, t)`, `sockets(island)`, `has(island, a)`, `count(island)`

`sockets` = every empty coord adjacent to an owned tile. That is where the child may build.

- [ ] **Step 1: Write the failing test**

```ts
import { describe, it, expect } from 'vitest'
import { createIsland, place, sockets, has, count } from '../../src/island/world/grid'
import { key } from '../../src/island/world/hex'

describe('island grid', () => {
  it('starts as Fred\'s one lonely rock', () => {
    // Brief section 3: the opening is one hex in a calm sea
    const i = createIsland()
    expect(count(i)).toBe(1)
    expect(has(i, { q: 0, r: 0 })).toBe(true)
  })

  it('offers exactly six sockets around a single tile', () => {
    expect(sockets(createIsland())).toHaveLength(6)
  })

  it('never offers a socket where a tile already is', () => {
    let i = createIsland()
    i = place(i, { q: 1, r: 0 }, 'grass')
    const s = sockets(i).map(key)
    expect(s).not.toContain(key({ q: 0, r: 0 }))
    expect(s).not.toContain(key({ q: 1, r: 0 }))
  })

  it('grows the socket ring as the island grows', () => {
    let i = createIsland()
    const before = sockets(i).length
    i = place(i, { q: 1, r: 0 }, 'grass')
    expect(sockets(i).length).toBeGreaterThan(before)
    expect(count(i)).toBe(2)
  })

  it('placing is immutable — the previous island is unchanged', () => {
    const a = createIsland()
    const b = place(a, { q: 1, r: 0 }, 'water')
    expect(count(a)).toBe(1)
    expect(count(b)).toBe(2)
  })

  it('remembers each tile type', () => {
    const i = place(createIsland(), { q: 1, r: 0 }, 'water')
    expect(i.tiles.get(key({ q: 1, r: 0 }))).toBe('water')
  })

  it('sockets are unique — a coord adjacent to two tiles appears once', () => {
    let i = createIsland()
    i = place(i, { q: 1, r: 0 }, 'grass')
    const s = sockets(i).map(key)
    expect(new Set(s).size).toBe(s.length)
  })
})
```

## Self-review notes

**Spec coverage.** Spec §7's module list maps to Tasks 1–11. The layer boundary (world raises intents → `flow` mediates → overlay mounts challenges) is Task 5, and it is pure, so it is tested without a GPU.

**Known gaps, stated rather than hidden.**
- Three.js rendering itself is not unit-tested; there is no GPU in CI. The pure layers (`hex`, `grid`, `flow`) are, and they hold the logic worth testing. Rendering correctness is judged by eye, on the device.
- The pick-of-three tile UI has no automated test; it is a DOM surface judged visually.
- Perf on the actual tablet is unknown until Task 4 deploys. That gate is deliberately early, while the scene is still cheap to change.
